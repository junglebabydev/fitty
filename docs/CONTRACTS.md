# Module contracts (build against these — do not rename exports)

Project: the repository root (all paths below are relative to it) — Vite + React 18 + TypeScript (strict) + Tailwind v4 (`@import "tailwindcss"` in `src/index.css`) + react-router-dom v6 + lucide-react + sql.js. Personal, single-user, local-first iPhone-style app. Read `docs/PRD.md` for product rules.

## Conventions
- Relative imports only. Dates: `'YYYY-MM-DD'` local strings; timestamps: ISO strings. Helpers in `src/lib/util.ts` (`todayStr, addDays, startOfWeek, daysBetween, dateOf, fmtDuration, fmtTime, fmtDate, dayName, isoAt, nowIso, clamp, round, cx, hourNow`).
- Domain types: `src/domain/types.ts` (do not edit; extend only via additive optional fields if truly needed and say so in your report).
- DB: `src/db/database.ts` exports `db` (sync sql.js wrapper): `db.all<T>(sql, params)`, `db.get<T>(sql, params)`, `db.run(sql, params): number` (returns last insert id), `db.exec(sql)`, `db.transaction(fn)`, `db.subscribe(cb)`, `db.export()`, `db.exportJson()`, `db.wipe()`. Schema in `src/db/schema.ts`. Booleans stored as 0/1, JSON as `*_json` TEXT.
- Repositories are **synchronous** (sql.js is sync). Screens re-render via `useQuery` (below) which subscribes to `db`.
- Units: metric internally (kg, cm, minutes). Protein is visually more prominent than carbs/fat everywhere.
- Never diagnose, never moralize about food, no streak-shaming, no social features.
- Typecheck: `npx tsc -p tsconfig.app.json --noEmit`. Tests: `npx vitest run` (vitest is installed; tests live in `src/**/__tests__/*.test.ts`).
- Only edit files you own (listed per task). Do not run `npm install`.

### Setup gate (`src/features/onboarding/setup.ts` + `SetupGate.tsx`)
The intake may be skipped from the welcome screen (`skipOnboarding()` writes the ISO setting `onboarding.skippedAt`; `commitIntake` clears it). `App`'s `OnboardingGate` then lets the profile browse instead of redirecting to `/onboarding`, and the gated actions refuse until `profile.onboarded` is true.
- `setup.ts`: `ONBOARDING_SKIP_KEY`, `GatedAction = 'workout'|'mobility'|'meal_photo'|'progress_photo'|'report'`, `GATE_COPY`/`gateCopy(action)`, `isOnboarded()`, `onboardingSkipped()`, `skipOnboarding()`, `clearOnboardingSkip()`, `canDo(action)`.
- `SetupGate.tsx`: `useSetupGate(): { ready, require(action): boolean, sheet }` (`require` reads the database synchronously, so a photo picker still opens inside the user's tap), `RequireSetup` (route wrapper → `SetupRequired`), `SetupLockCard` (inline stand-in for a locked control), `SetupPrompt` (Today's reminder while the intake is unfinished).
- Locked: `/train/session/:id`, `/train/mobility`, planning or starting a session from Train and Today, meal photos in the Composer, progress photos in Progress, report uploads in Reports. Everything else (browsing, check-ins, text meal logs, Mind, Coach, Settings) stays open.

## `src/engine/` (engine task) — pure functions, NO db/react imports, fully unit-tested
- `readiness.ts`: `computeReadiness(input: ReadinessInput): ReadinessResult`.
  `ReadinessInput = { sleepLastNightMin: number|null, sleepAvg7Min: number|null, symptoms: SymptomCheck[] /*today*/, checkIn: DailyCheckIn|null, restingHr?: number|null, restingHrBaseline?: number|null, sessionsLast7: number }`.
  `ReadinessResult = { state: Readiness, reasons: string[], modifiers: { reduceVolume: boolean, lowImpactOnly: boolean, avoidRegions: Region[], suggestRest: boolean } }`.
  Rules (PRD §9.3, §11): any red flag (locking/givingWay/numbness/weakness/radiating) or pain > 5 → RED. Pain 3–5 → AMBER. Sleep < 5.5h alone → AMBER (reduce volume, not rest). Sleep < 7h **and** (pain 1–2 or soreness ≥ 3 or energy ≤ 3) → AMBER. Sleep < 7h alone → GREEN with a caution reason. RHR ≥ baseline + 7 → AMBER. Never RED from sleep alone. Reasons are short human strings like `"6h 10m sleep, below 7-day average"`, `"Mild knee soreness (2/10)"`.
- `symptomGate.ts`: `evaluateSymptomGate(symptoms: SymptomCheck[]): GateResult` where `GateResult = { regions: {region: Region, level: 'OK'|'AMBER'|'RED', reasons: string[]}[], avoidTags: SafetyTag[], overall: 'OK'|'AMBER'|'RED', advice: string[] }`. Mapping: knee AMBER → avoid `impact`,`deep_knee_flexion`; knee RED → also `knee_load`; back AMBER → avoid `spinal_flexion`,`axial_load`; back RED → also `spinal_load`; neck AMBER → avoid `overhead`; neck RED → also `neck_load`. Red flags force RED. `isExerciseAllowed(ex: Exercise, gate: GateResult): {allowed: boolean, reasons: string[]}`, `findSubstitute(ex: Exercise, gate: GateResult, library: Exercise[]): Exercise | null` (prefer listed substitutions, then same pattern, no avoided tags, prefer machines/dumbbells).
- `progression.ts`: `evaluateProgression(planned: PlannedExercise, exercise: Exercise, lastSets: ExerciseSet[], previousSets: ExerciseSet[]): ProgressionResult` with `ProgressionResult = { nextLoadKg: number|null, repMin: number, repMax: number, action: 'increase'|'hold'|'deload'|'start', reason: string, stalled: boolean }`. Double progression: all sets ≥ repMax with RIR ≥ 1 and no painFlag → increase (dumbbell +2 kg per hand → step 2; machine/cable +5%; bodyweight → add reps). Any painFlag or any set below repMin → hold. Below repMin two sessions in a row → stalled=true, action 'deload' (−10%). `estimate1RM(loadKg, reps): number` (Epley). `loadIncrement(equipment): number`.
- `nutrition.ts`: `estimateTargets(p: {sex, dob, heightCm, weightKg, activity: 'low'|'moderate'|'high', goal: 'cut'|'maintain'|'gain'}): {kcal, proteinG, carbsG, fatG, rationale}` (Mifflin-St Jeor; cut = −500 (floor 1,600); protein 1.8 g/kg rounded to 5; fat 0.8 g/kg; carbs remainder). For the seed profile (the fictional demo persona: male, 1989-02-11, 179 cm, 84 kg, moderate, cut) it must return ≈2,050 kcal / 150 g protein. `evaluateNutritionTrend(input: { weights: BodyMetric[], waists: BodyMetric[], intake: {date, kcal, proteinG, logged}[], target: NutritionTarget, windowDays?: number }): TrendResult` where `TrendResult = { weeklyRateKg: number|null, avg7Kg: number|null, prevAvg7Kg: number|null, loggedDays: number, adherencePct: number, avgKcal: number|null, avgProteinG: number|null, flags: {kind: 'under_eating'|'low_protein'|'rapid_loss'|'flat'|'on_track'|'insufficient_data', message: string}[], proposal: ProposedAction|null, evidence: Evidence[] }`. Flat = |rate| < 0.15 kg/wk over ≥14 days with adherence ≥ 80% → proposal `nutrition_target` −150 kcal. Rapid loss = rate < −1.2 kg/wk → proposal +150 kcal. Under-eating = avg kcal < 1,500 over ≥5 logged days. Low protein = avg < 70% target.
- `trends.ts`: `rollingAverage(points: {ts: string, value: number}[], days: number, endDate: string): number|null`, `weeklyRate(points, endDate): number|null` (avg of last 7 minus avg of prior 7), `projectDate(current: number, target: number, ratePerWeek: number, fromDate: string): string|null`, `dailySeries(points, days, endDate): {date, value: number|null}[]`.
- `planner.ts`: exports `SESSION_TEMPLATES: Record<string, {key, name, type: SessionType, tier, estMin, exercises: PlannedExercise[]}>` (keys: `upper_a`, `lower_a`, `full_b`, `conditioning_bike`, `swim`, `mobility_hips`, `mobility_upper`; use canonical exercise IDs below; lower_a is knee-friendly: leg press moderate ROM, hip thrust/glute bridge, hamstring curl, leg extension light, calf raise; no deep squats). `buildWeek(weekStart: string, tier: 'minimum'|'target'|'stretch'): Omit<WorkoutSession,'id'>[]` (minimum = 3 strength; target = +conditioning; stretch = +swim/mobility). `reflowWeek(sessions: WorkoutSession[], today: string): {id: number, scheduledDate: string, note: string}[]` — move missed (planned & date < today) sessions forward into remaining days of the week, one session/day, protect the 3 strength minimum first, drop stretch-tier items if days run out; never move completed/skipped. `shortenedVersion(exercises: PlannedExercise[]): PlannedExercise[]` (25–35 min: keep first 4 compounds, 2 sets each). `applyGateToSession(exercises: PlannedExercise[], gate: GateResult, library: Exercise[]): {exercises: PlannedExercise[], changes: string[]}` (substitute disallowed exercises).
